### 1.2 后端与后台管理证据（单一契约源）

| 契约层 | 真实来源 | 必须对齐 |
| --- | --- | --- |
| 路由 | `SparkService/medical/urls.py` | `router.register("health-exam-reports", HealthExamReportViewSet)`；`med-exam-details` ViewSet；统一门面 `resources`；`POST workflows/health-exams/save/` |
| 模型 | `medical/models.py` → `HealthExamReport`、`MedExamDetail` | `ExamType` 1–4；`Source` 1–3；`Status` 1–3；`BusinessType.HEALTH_EXAM_REPORT="health_exam_report"` |
| Serializer | `HealthExamReportSerializer`、`MedExamDetailSerializer` | 字段表见 §5；读出时 `raw_ocr` 被 `to_representation` pop |
| 工作流 | `HealthExamWorkflowSaveView` | 原子保存报告 + details + `file_ids` 绑定 `health_exam_report` |
| 权限 | Serializer `validate_member` | 非 staff 须有 active binding |
| 响应包裹 | `common/response.success_response` | `{code,msg,data}`；save 返回 `data.id`（及 report/details） |
| 后台管理 | admin medical-data complete-data | **另一套摘要 payload**，禁止当客户端契约 |

**同源结论：** 客户端只消费 `/api/v1/medical/...`；不得新增平行 path 或改写 `business_type`。Examination vs HealthExam 在后端是两套 ViewSet，禁止混用。

### 1.3 参考端与目标端

- **参考端：** `SparkClient`；总领 `体检报告.md`（流程第三～八节；UI/模型见 §二点五）。
- **目标端：** `SparkClientHarmonyOS`；独立列表/卡片/详情/懒加载/删档已通；上传 OCR / 分享 / Chat 待实现。
- **目标用户能力：** 查看当前成员体检列表（缓存首屏）、筛选搜索、下拉刷新、归档切换；进入详情看指标；删除/归档；上传识别入库（待）；分享/问报告（待）。

### 1.4 结论

| 类别 | 项 |
| --- | --- |
| 已对齐（契约/设计） | kind=`health-exam-reports`；资源 business=`health_exam_report`；列表 refresh + 活跃 patch；归档不回写活跃缓存；明细 `business_type=health_exam_report` |
| HarmonyOS **部分实现** | `HealthExamReportsListPage` + `ExamReportCard` + Detail + LazyLoad + Workflow save/delete/archive + DTO 明细 |

### 2.6 项目架构原则与依赖方向（强制）

**分层依赖方向（与 iOS 一致）：**

```text
Presentation（HealthExamReports* / ExamReportCard / HomeTab 装配）
        ↓ 只依赖
Application 共享编排（懒加载 Controller；未来 Upload VM）
        ↓
Infrastructure API（MedicalQuery / Workflow / Sync DTO）
        ↓
Core Networking Engine → 后端 /api/v1/medical/...

Home 缓存权威源：HomeViewModel.completeData.healthExamReports
        ↑ 唯一回写
HomeMedicalRouteSupport.patchHealthExamReports / removeHealthExamReport
```

**原则：**

1. **无第二缓存真相：** 禁止 Disk/Preferences/旁路 Store 持久化体检快照；活跃列表权威在 `HomeViewModel`（见缓存方案）。归档模式 `onReportsUpdated=null`，**禁止** patch 活跃数组。  
2. **无页面直连 HTTP：** 禁止 `http.createHttp()`；一律经 Network Engine + Query/Workflow。  
3. **DTO 主路径：** UI 消费 `RemoteHealthExamReportWithAttachments`；Domain 实体可选，不得另造平行字段名。  
4. **写路径单一契约：** 保存只走 `workflows/health-exams/save/`；删除/归档走统一资源 kind=`health-exam-reports`。  
5. **Chat 只读：** 问报告不得反向驱动体检写路径。  
6. **与检查报告隔离：** 不得复用检查目录名、`examination_report` business_type、或 `medical-reports/create/`。

```text
HomeTab 卡片 Kind.HEALTH_EXAM_REPORTS
  → NavPathStack push(home.medical.healthExam)
  → HealthExamReportsListPage
      ↓ 读 completeData.healthExamReports
      ↓ 懒加载 / 刷新
  MedicalQueryAPI → 网络 Engine
      ↓ 活跃成功
  HomeMedicalRouteSupport.patchHealthExamReports → HomeViewModel

详情
  → HomeViewModel.healthExamDetailTarget
  → NavPathStack push(home.medical.healthExam.detail)
  → delete / setArchived → removeHealthExamReport + bumpHealthExamListRevision

上传确认（待）
  → MedicalDocumentUpload → Workflow.saveHealthExam
  → 成功后 upsert/refresh list → patch
```

## 4. 核心关键技术与实现方案

### 4.1 列表首屏与缓存消费（部分实现）

1. **目标：** 活跃列表零二次 complete-data 请求直出。  
2. **iOS：** `HealthExamReportsListPage` 初始化吃 `completeData.healthExamReports`（总领第三节）。  
3. **HarmonyOS 当前：** `HealthExamReportsListPage.hydrateFromCache` → `homeVm.completeData().healthExamReports`；持有完整 `RemoteHealthExamReportWithAttachments[]`（**已非**标题壳）。  
4. **归档：** `archiveMode=ARCHIVED` 时清空本地、切断 patch，独立 `list(..., archived=true)`。  
5. **官方：** [Navigation](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-basic-components-navigation) — `NavPathStack` + `navDestination`；目的地 Builder 必须以 `NavDestination` 为唯一根；按 API Level **24** 复核。  
6. **本地示例（结构）：** Parking `HomePageVM`（仅借鉴 VM 聚合 / `Promise.allSettled`；**禁止**复制业务 Https）。  
7. **验收：** 有缓存进页不发 complete-data；归档操作不污染活跃 `healthExamReports`。

### 4.2 明细懒加载（部分实现）

1. **目标：** `detailsLoaded == false` 才请求；同 ID 单飞；成功活跃 patch。  
2. **iOS：** `MedExamDetailLazyLoadViewModel`；`business_type=health_exam_report`；accepted 含 `health_exam`。  
3. **HarmonyOS 当前：** `HealthExamDetailLazyLoadController` + `listMedExamDetails`；accepted=`health_exam_report`/`health_exam`；列表 `prefetchVisibleDetails`。  
4. **并发：** `loadingIds`；失败保持未加载可重试；失败不弹阻塞 toast。  
5. **注意：** 列表异常统计用 `HealthExamFlagSupport.isPotentiallyAbnormalFlag`；详情风险用 `inferredRiskLevel`——两套规则不同（见 iOS §二点五·2.5.3）。

### 4.3 下拉刷新与字段 patch（部分实现）

1. **API：** `GET /api/v1/medical/resources/?kind=health-exam-reports&member_id=&archived=`。  
2. **活跃：** `HomeMedicalRouteSupport.patchHealthExamReports`；**归档：** 不 patch。  
3. **失败：** `NotificationClient.error`；不写空数组覆盖缓存。  
4. **副作用：** 刷新后明细通常清空/`detailsLoaded=false`，需再次懒加载。  
5. **已知缺口：** patch **不重算** 首页 `cards` 计数（与缓存方案一致）。

### 4.4 工作流保存 / 删除 / 归档 / 分享（mutation · 部分实现）

1. **Save：** `POST /api/v1/medical/workflows/health-exams/save/` — API **已有**；上传 UI **未接**。  
2. **Delete：** 统一资源 delete，`kind=health-exam-reports` — 详情 **已接**。  
3. **Archive：** `setHealthExamArchived` + `HealthExamArchiveMutationService` — 详情 **已接**。  
4. **Share：** `business_type=health_exam_report` — **待** 详情菜单接线。  
5. **官方 HTTP：** [发送网络请求（ArkTS）](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/http-request) — 经 Engine，禁止页面直连。  
6. **安全：** 不把 `raw_ocr`、附件 URL、Token 打进 hilog；Preferences 不存报告正文。

### 4.5 上传识别（待实现 · upload）

- AI scenario：`health_exam_extraction`（常量已有）。  
- 文档 kind：`healthExamReport`；底部仅「拍摄添加」；max 文件 **6**；Sheet 默认文件选择（对齐 iOS，异于检查报告默认相机）。  
- 本模块只定义入口契约；OCR/OSS 细节引用上游文件与 OCR 方案。  
- **禁止**走病历组合包创建路径。

### 4.6 ArkTS 职责骨架（与当前实现同构示意）

```ts
// 伪代码 / 示意 — 对照当前 HealthExamReportsListPage；不可直接粘贴为生产实现
class HealthExamReportsListViewModel {
  reports: RemoteHealthExamReportWithAttachments[] = [];
  loadingIds: number[] = [];

  hydrate(complete: RemoteMemberCompleteData | undefined, mode: MedicalArchiveListMode): void {
    if (mode === MedicalArchiveListMode.ACTIVE && complete) {
      this.reports = complete.healthExamReports.slice();
    } else {
      this.reports = [];
    }
  }

  async refresh(query: SparkMedicalQueryAPI, memberId: number, mode: MedicalArchiveListMode,
    homeVm: HomeViewModel): Promise<void> {
    const list = await query.listHealthExamReportsWithAttachments(memberId, medicalArchiveQueryForMode(mode));
    this.reports = list;
    if (mode === MedicalArchiveListMode.ACTIVE) {
      HomeMedicalRouteSupport.patchHealthExamReports(homeVm, list);
    }
  }

  // 已由 HealthExamDetailLazyLoadController 落地：
  // detailsLoaded==false && !loading → listMedExamDetails → 回写 + ACTIVE patch
}
```
