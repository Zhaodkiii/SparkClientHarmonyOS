### 1.2 后端与后台管理证据

本模块**不新增 HTTP 契约**。全量快照仍来自上游接口方案中的：

| 契约 | 路径 | 与缓存关系 |
| --- | --- | --- |
| 客户端 complete-data | `GET /api/v1/medical/members/{id}/complete-data/` | 唯一全量写入源；ETag 86400 属网络层，不是本模块 DiskCache |
| 各资源 list（局部刷新） | `GET /api/v1/medical/resources/?kind=...` 等（见接口方案 §5） | 列表成功后 **只 patch 对应字段**，不重拉 complete-data |
| 后台 admin complete-data | `/api/admin/v1/medical-data/.../complete-data/` | **禁止**当作客户端缓存 payload |

**同源结论：** 缓存是客户端进程内对后端客户端 complete-data 的投影；后台摘要 payload 不得进入 `HomeDashboard.medical.completeData`。

### 1.3 参考端与目标端

- **参考端：** `SparkClient`；总领 `首页医疗数据缓存.md`；关键实现 `HomeViewModel`、`HomeMedicalRouteSupport`、`MedicalLists/**`、`FamilyMedicineCabinetPage`、`ChatView`/`ChatDetailViewModel`。
- **目标端：** `SparkClientHarmonyOS`；首屏已能持有 `completeData` 并同成员保留 `familyMedicineBoxes`；**尚无**字段 patch、列表注入、Chat 镜像。
- **目标用户能力：** 进入病历/体检/检查/用药列表首屏直出缓存；下拉只刷当前资源并回写单字段；同成员首页 refresh 不丢家庭药箱；切换成员不串快照。

### 1.4 结论

| 类别 | 项 |
| --- | --- |
| 已对齐（契约/设计） | 权威源 = `HomeViewModel.dashboard.medical.completeData`；无独立 Cache Store；无 Disk 持久化健康快照；`familyMedicineBoxes` 懒字段 + 同成员保留 |
| HarmonyOS 已落地 | Domain 字段、UseCase 全量写入、load 时家庭药箱合并、`completeData()`、`updateMedicalCompleteData`、`reloadMembers`、`HomeMedicalRouteSupport`、四列表首屏缓存+刷新 patch、家庭药箱懒写、账号切换清 HomeVM；`assembleHap` 已通过 |
| HarmonyOS 待实现 | Chat 镜像与 `memberId` 校验；列表明细/表单/OCR/提醒重建等深度能力 |
| 已知参考端缺口（两端共记） | patch **不重算** `cards`；`syncRemote: false` **未**跳过网络；无缓存专项单测；`moduleSetupCache` 未自动回写首页 |
| 不适用 | 把 `MedicationExecutionRecordCache` 写成首页缓存；把 complete-data 写入 Preferences/RDB |

## 3. 分层职责与请求链路

### 3.1 分层

| 层 | 职责 | 不做 |
| --- | --- | --- |
| Domain | `HomeMedicalOverview.completeData` 字段定义 | HTTP、UI |
| Application | 全量拉取写入（上游 UseCase） | 字段 patch |
| Presentation（HomeVM） | 持有、合并家庭药箱、`updateMedicalCompleteData`、失效/重建 | 列表 HTTP |
| Presentation（RouteSupport） | 注入引用 + 回调 → patch | 自持权威快照 |
| Presentation（Lists/药箱/Chat） | 首屏直出；成功后回调单字段 | 各自再拉 complete-data（有缓存时） |

### 3.2 主流程

```text
首页 load / 切换成员
  → UseCase：listMembers + fetchMemberCompleteData
  → HomeVM 写入 dashboard（同成员 merge familyMedicineBoxes）
  → 用户进入列表/药箱/Chat
  → 注入 completeData（memberId 一致才复用）
  → 子页首屏直出
  → 下拉/增删改成功 → updateMedicalCompleteData { 单字段 }
  → notify UI / Chat onChange
```

### 3.3 事件与缓存行为

| 阶段 | 触发 | 输入 | 参与模块 | 成功 | 临时失败/恢复 | 永久失败/清理 | 用户可见 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 首屏写入 | `loadInitialIfNeeded` | session、selectedMemberID | UseCase、HomeVM | dashboard+completeData | complete-data 失败 → `completeData=nil`+空卡片 | listMembers 失败 → toast，**保留旧 dashboard** | loading → 卡片/空 |
| 强制刷新 | `refresh` / `forceReload` | syncRemote=true | 同上 | 整表替换；同成员保留家庭药箱 | 同上 | 同上 | 刷新中 |
| 切成员 | `selectMember` / `switchMemberAndLoad` | 新 memberID | HomeVM | **新快照**；旧 family 不带入 | complete 失败空卡 | 成员列表失败保留旧 | 新成员数据 |
| 仅成员条 | `reloadMembers`（待实现） | — | LoadMembers、HomeVM | 更新 members，**保留 medical** | 局部失败吞空（Repository） | — | 成员条变，卡片不变 |
| 字段 patch | 列表回调 | 单字段数组 | RouteSupport、HomeVM | 只改目标字段 | 刷新失败不回写 | `completeData==nil` 则忽略 | 再进列表见新数据 |
| 家庭药箱懒写 | 药箱加载成功 | boxes | 药箱页 → patch | 写 `familyMedicineBoxes` | 失败保留旧、不写空 | — | 药箱有数据 |
| 登出 | account clear | — | AppContainer | HomeVM 缓存释放 | — | 清空 Preferences 选中成员（非 completeData） | 回登录 |

### 3.4 并发与幂等

| 规则 | 说明 |
| --- | --- |
| 首屏防重入 | iOS `isInitialLoadInFlight`；HarmonyOS 现用 `initialLoadStarted` + `loadGeneration`（需验收与 Coordinator 双触发） |
| generation 丢弃 | 旧请求返回时 generation 不匹配则丢弃，防止串成员 |
| patch | 同步赋值；同字段后写覆盖先写 |
| 归档 | `MedicalArchiveListMode.ARCHIVED` 时不挂 `onXxxUpdated`，防污染活跃缓存 |
| `syncRemote` | **当前两端均未**用该参数跳过网络；文档记为已知缺口，不得写成已交付能力 |

## 4. 核心关键技术与实现方案

### 4.1 内存快照持有与读取

**目标：** 唯一权威源在 `HomeViewModel.dashboard?.medical.completeData`。

**iOS 证据：** `HomeDashboard.swift`；`HomeViewModel.load` 组装；`completeData` 注入见 `HomeMedicalRouteSupport.medicalListView`。

**HarmonyOS 现状：** Domain + UseCase 写入 + `completeData()` getter 已有；列表尚未调用。

**官方能力：** 本子节为进程内对象图，不依赖 Preferences。禁止用 Preferences 存 complete-data（健康敏感、体积大）。Preferences 仅用于**选中成员 ID**（见 MemberContext / 上游接口方案）。

- Preferences 指南（需按 API Level 复核）：[通过用户首选项实现数据持久化](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/data-persistence-by-preferences)  
- API 参考：[用户首选项 Preferences](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-data-preferences)

**本地示例：**

| 路径 | 可借鉴 | 禁止复制 |
| --- | --- | --- |
| `.../agc-template-market-harmonyos-demos-main/LifestyleAndServiceTemplate/Parking/features/tab/home/src/main/ets/viewmodels/HomePageVM.ets` | Tab 首页 VM 持有状态、单例分发 | 硬编码 endpoint、Mock 业务、把业务缓存写成全局单例权威源 |
| 工程内 `LegalAcceptanceStore.ets` / `SelectedMemberIDStore.ets` | Preferences 账号隔离模式 | 把医疗快照塞进 Preferences |

**伪代码（职责骨架，未编译验证）：**

```ts
// 伪代码：权威读取
function injectCompleteData(homeVm: HomeViewModel): RemoteMemberCompleteData | undefined {
  return homeVm.dashboard?.medical.completeData;
}
```

**验收：** 有快照时列表首屏不请求 complete-data；无快照时下游不得假装缓存成功。

### 4.2 字段级回写 `updateMedicalCompleteData`

**目标：** 只改目标字段；无 dashboard/completeData 时静默 return。

**iOS 证据：**

```swift
func updateMedicalCompleteData(
    _ transform: (inout SparkMedicalSyncAPI.RemoteMemberCompleteData) -> Void
) {
    guard var dashboard else { return }
    guard var completeData = dashboard.medical.completeData else { return }
    transform(&completeData)
    dashboard.medical.completeData = completeData
    self.dashboard = dashboard
}
```

接线表（与总领一致）：

| 回调 | 字段 | 典型触发 |
| --- | --- | --- |
| `onMedicalCasesUpdated` | `medicalCases` | 病历刷新/增删改 |
| `onHealthExamReportsUpdated` | `healthExamReports` | 体检刷新/明细懒加载/删除 |
| `onExaminationReportsUpdated` | `examinationReports` | 检查刷新/明细/时间线补丁 |
| `onMedicationPlansUpdated` | `medicationPlans` | 用药计划（可触发提醒重建） |
| `onPrescriptionsUpdated` | `prescriptions` | 处方 |
| `onMedicineBoxesUpdated` | `medicineBoxes` | 个人药箱 |
| `onMemberCompleteDataChanged` | `familyMedicineBoxes` | 家庭药箱 |

**HarmonyOS 目标文件：** `HomeViewModel.ets` 增加同名方法；ArkTS 用显式拷贝或就地改字段后 `notify()`（参考现有 `setOnChanged`）。

**伪代码：**

```ts
// 伪代码
updateMedicalCompleteData(mutator: (data: RemoteMemberCompleteData) => void): void {
  const dash = this.dashboard;
  if (!dash || !dash.medical.completeData) {
    return;
  }
  mutator(dash.medical.completeData); // 仅改目标字段
  this.notify();
  // 已知缺口：此处不重算 cards（与 iOS 一致，演进项可加 recomputeCards）
}
```

**安全/并发：** 不写日志完整病例正文；失败列表结果不得 mutator 进缓存。

**验收：** 只改目标字段；失败不回写；归档模式无回调。

### 4.3 注入接线 `HomeMedicalRouteSupport`

**目标：** 卡片跳转 → 列表页带上同一份 `completeData` + patch 回调。

**iOS 证据：** `HomeMedicalRouteSupport.swift`。

**HarmonyOS 目标：** `Projects/Features/Home/Presentation/HomeMedicalRouteSupport.ets`；路由推入遵循工程 Navigation 规范（自定义目的地根节点必须是 `NavDestination`，禁止嵌套业务 `Navigation`）。

**官方：** [组件导航 Navigation](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-navigation-navigation)（API Level 随工程 24 复核）。

**本地示例：** `HouseAndHomeTemplate/HomeDecoration/.../MainEntry.ets`（Navigation+Tabs）；禁止复制示例业务 URL。

**验收：** 四卡进入对应列表均注入；回调命中正确字段。

### 4.4 家庭药箱懒写入与同成员保留

**目标：** complete-data **默认不含** `family_medicine_boxes`；药箱页成功后写入；同成员全量 refresh 合并保留。

**iOS 证据：** `HomeViewModel.load` 合并；`FamilyMedicineCabinetPage` 回写。

**HarmonyOS 现状：** load 合并段**已实现**；药箱页与回写**待实现**。

**规则：**

1. `memberId` 相同且旧缓存有 `familyMedicineBoxes` → 拷到新快照。  
2. 切成员 → 不得带入旧家庭药箱。  
3. 药箱刷新失败 → 不回写空数组。

### 4.5 Chat 镜像（下游预留）

**目标：** `ChatDetailViewModel.cachedMemberCompleteData` 随首页 `onChange` 同步；问报告仅当 `initialCompleteData?.memberId == memberID` 命中。

**HarmonyOS：** Chat Feature 未落地前，本方案只定义契约；实现时不得在 Chat 内再拉一份「权威」complete-data 分叉。

### 4.6 旁路机制隔离

| 机制 | 所有者 | 与本缓存 |
| --- | --- | --- |
| `dashboard.medical.completeData` | HomeViewModel | **权威** |
| `moduleSetupCache` | 成员维护 VM | 独立；当前 iOS 未确认自动回写首页 |
| Chat `cachedMemberCompleteData` | ChatDetail VM | 镜像 |
| `MedicationExecutionRecordCache` | 用药执行中心 | **无关** |

## 5. 接口契约与数据模型

### 5.1 通用状态（本模块）

| 模型/属性 | 外部字段名 | ArkTS 类型 | 必填 | 敏感 | 来源与验证 | 生命周期/持久化 | 兼容规则 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `completeData` | 无（内存） | `RemoteMemberCompleteData \| undefined` | 否 | **高**（健康） | UseCase / patch | 仅内存；登出释放 | 禁止 Preferences/RDB |
| `cards` | 无 | `MedicalCard[]` | 是（可空统计） | 低 | 仅全量 load 投影 | 与 load 绑定 | patch **不**更新（已知缺口） |
| `familyMedicineBoxes` | JSON `family_medicine_boxes`（懒） | `RemoteMedicineBox[] \| undefined` | 否 | 高 | 药箱页 / merge | 同成员跨 refresh | 跨成员清空 |
| 选中成员 ID | Preferences `memberContext.selectedMemberID.{accountId}` | `number \| undefined` | 否 | 低 | SelectedMemberIDStore | 账号级 | **非** completeData |

完整 `RemoteMemberCompleteData` 字段字典 → 见 [`首页医疗接口详细技术方案.md`](./首页医疗接口详细技术方案.md) §5.3–5.9。

### 5.2 操作契约

| 操作 | 输入/输出 | 后端/系统 | 鉴权 | 错误与 Request ID | 缓存/并发 | 消费位置 | 证据 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 全量写入 | 入：API `data`；出：`completeData` | complete-data GET | Bearer + 成员权限 | 失败降级 nil；requestId 走网络层 | ETag 86400 在 Engine | HomeVM | 接口方案 + UseCase |
| 字段 patch | 入：单字段数组；出：同对象就地更新 | 各 `list*` 成功后客户端 | 同左 | 失败不 patch | 同步；无 completeData 则忽略 | RouteSupport | iOS HomeVM |
| 列表注入 | 出：`completeData?` | 无新 HTTP | — | 无缓存则列表自行 list | 只读引用/拷贝 | MedicalLists | RouteSupport |
| 家庭药箱保留 | 入：新旧 completeData | 无 | — | — | `memberId` 相等才 merge | HomeVM.load | HomeVM.ets 已有 |
