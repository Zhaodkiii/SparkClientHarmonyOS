## 1. 对标范围与结论

### 1.1 功能范围

本文对齐 iOS 端以下能力：

- 家庭药箱：按入口成员汇总创建者名下全部成员药品与家庭公共药品，支持成员筛选。
- 个人药箱：只展示入口成员绑定的药品，供成员医疗列表和用药执行中心使用。
- 药品列表：类型筛选、关键字搜索、更新时间排序、双列卡片、过期/临期/低库存角标。
- 药品创建与编辑：归属、名称、类型、品牌、剂型、规格、剂量单位、总数量、有效期、备注和附件。
- 药品详情：归属、库存、有效期、附件和操作菜单。
- 资源生命周期：删除、归档、取消归档。
- 文件能力：药品图片/附件关联，以及药箱拍照识别入口。
- 上游缓存：家庭模式回写 `familyMedicineBoxes`，个人模式回写 `medicineBoxes`。
- 跨模块关系：药箱可被服药计划引用，但药箱模块不负责服药频率、提醒和服药记录。

不在本文直接实现范围内：

- 处方 OCR 的完整识别算法；本文只定义药箱识别结果如何进入药箱写入链路。
- 服药计划的周期计算、提醒注册和服药记录生成。
- 后端数据库迁移、权限规则和后台管理页面实现。
- Token、安全存储、通用 HTTP Engine、OSS SDK 本身的重新设计；本文引用现有 HarmonyOS 上游方案。

### 1.3 后端与后台管理单一契约要求

当前仓库没有在 `SparkClientHarmonyOS` 内包含 `SparkService` 后端源码。因此：

- API path、HTTP method、JSON 字段名以 iOS 现有调用和同一后端契约为基线。
- 后端的最终 Serializer、权限、业务码、响应包装、request ID、归档约束和后台管理关联仍需由 `SparkService` 源码或 OpenAPI 最终确认。
- HarmonyOS 不得根据 ArkTS 属性名另造字段，不得为了适配页面增加仅 HarmonyOS 使用的 endpoint。
- 后台管理端如果存在不同入口，只能作为同一领域模型的另一入口；不能把后台 payload 当作客户端 payload。

需要向后端确认的具体契约：

1. `POST/PATCH /api/v1/medical/resources/?kind=medicine-boxes` 的完整请求体与返回对象。
2. 药箱资源归档是否统一使用 `PATCH /api/v1/medical/resources/{id}/?kind=medicine-boxes` 和 `{ "is_archived": true }`。
3. 删除被 `MedicationPlan` 引用的药箱时，服务端是拒绝、解除引用、级联删除还是仅软删除。
4. `member=null` 的公共药品是否允许由所有已绑定成员编辑。
5. `entry_member_id` 是否是 Serializer 必填字段、仅用于权限范围，还是只在 workflow save 使用。
6. 附件 `file_ids` 的替换语义：全量替换、追加还是保留未传附件。

### 2.3 目录设计约束

1. 页面不能直接调用 `http.createHttp()`、`axios` 或 OSS SDK。
2. `MedicineBoxPage` 只消费 ViewModel 的 `viewState` 和 action，不直接修改 `HomeViewModel.completeData`；缓存 patch 通过 `HomeMedicalRouteSupport` 或 `MedicineBoxUseCase` 统一完成。
3. `RemoteMedicineBox` 只负责远端 DTO 解析；ArkUI 表单使用独立 `MedicineBoxFormModel`，避免输入中的半成品字符串污染远端模型。
4. 健康数据快照不进入 Preferences、AppStorage 或普通文件缓存；首页内存投影仍由 `HomeViewModel` 持有。
5. 所有新增文件必须进入 `AppContainer` 或目标页面可达的导航/组合根，单纯创建文件不算功能完成。
6. 目标目录可与 iOS 物理路径不同，但 `Home / Core / Features / Medical` 的业务职责必须一一对应。

| `MedicalQueryAPI` | GET 查询和解码 | 页面筛选、错误文案、弹窗 |
| `MedicalWorkflowAPI` | POST/PATCH/DELETE 资源调用 | 直接操作首页状态 |

### 3.6 页面状态机

```text
idle
  ├─ enter + cache → ready(cache)
  ├─ enter + no cache → loading(initial)
  └─ invalid member → unauthorized/invalidContext

loading(initial)
  ├─ success(non-empty) → ready
  ├─ success(empty) → empty
  ├─ network/5xx → error(no data)
  └─ cancel/disappear → idle/cancelled

ready
  ├─ pull refresh → refreshing
  ├─ create/edit → draft
  ├─ search/filter → ready(filtered)
  └─ archive mode → loading/archiveReady

draft
  ├─ valid submit → saving
  ├─ invalid submit → draft(validationError)
  └─ cancel/back → ready(previous)

saving
  ├─ success → ready(updated)
  ├─ 401/403 → unauthorized/permissionError
  ├─ validation → draft(serverValidationError)
  └─ network → draft(retryableError)
```

### 3.7 页面与状态绑定规则

| 状态 | ArkUI 展示 | 可操作项 |
|---|---|---|
| `loadingInitial` | `LoadingProgress` + 不显示误导空态 | 取消/返回 |
| `ready` | 卡片网格 | 搜索、筛选、详情、刷新、新增、上传 |
| `readyCachedRefreshing` | 保留卡片 + 顶部刷新指示 | 仍可浏览；不允许重复刷新 |
| `empty` | 空态说明 + 新增/上传入口 | 新增、上传 |
| `draft` | 表单 | 编辑、取消、保存 |
| `saving` | 保存按钮 loading/禁用 | 取消应禁用或明确中止语义 |
| `error` | 错误文案 + 重试 | 重试、返回、继续使用缓存 |
| `unauthorized` | 无权限/会话失效页面 | 重新登录或返回 |
| `archived` | 归档药品列表 | 详情、取消归档、删除 |

### 4.6 卡片状态规则

与 iOS 对齐的客户端展示规则：


- 过期：`expireDate` 的本地日期早于今天。
- 临期：今天 ≤ `expireDate` ≤ 今天 + 30 天。
- 库存不足：`totalQuantity` 非空且 `totalQuantity <= 0`。
- 优先级：过期 > 临期 > 库存不足。
- 以上只用于客户端提示，不替代服务端药品状态或权限判断。
- 日期比较必须使用统一的本地日历和 date-only 语义，不能直接比较带时区的 ISO 字符串。

### 4.7 列表性能与响应式布局

参考华为 Demo 中 `GridRow`/`GridCol` 的响应式边距思想，但药箱列表的具体设备适配仍需基于目标设备验证：

- 手机竖屏：两列卡片，左右安全边距 16。
- 折叠屏/平板：使用 `GridRow`/`GridCol` 或根据窗口宽度调整为 3–4 列，禁止硬编码固定屏宽。
- 长列表：使用懒加载 Grid/List，`ForEach` key 必须稳定使用 `box.id`，不能使用标题和 index 拼接作为唯一身份。
- 卡片图片：优先使用附件缩略图；无图使用基于 `id` 的稳定占位图，避免每次刷新变色。
- 筛选/搜索：在内存列表上派生，不对每个字符发网络请求。

### 4.8 表单与数据校验

客户端校验：

| 字段 | 校验 | 失败反馈 |
|---|---|---|
| `medicineName` | trim 后非空 | 表单字段错误，不发请求 |
| `totalQuantity` | 空值允许；非空必须能转换为非 NaN 数字 | 数量字段错误 |
| `expireDate` | 日期开关关闭传 null；打开传 date-only | 不允许传本地时间戳替代日期 |
| `medicineType` | 使用存储值，不直接提交显示文案 | 由目录映射 |
| `dosageForm` | 使用剂型存储值 | 允许兼容后端已有 legacy 值 |
| `strength` | 结构化规格编码或 legacy 文本 | 不丢失旧数据 |
| `member` | 家庭模式可 null/成员 ID；个人模式固定当前成员 | 服务端最终校验权限 |
| `fileIds` | 先上传成功再提交关联 ID | 上传失败不提交不完整关联 |

### 4.9 ArkTS DTO 解码要求

HarmonyOS 当前 `RemoteMedicineBox.fromJson` 只读取少量字段，目标应补齐：

```ts
export class RemoteMedicineBox {
  id: number = 0;
  member?: number;
  medicineName: string = '';
  medicineType?: string;
  brandName: string = '';
  dosageForm: string = '';
  strength: string = '';
  doseUnit: string = '';
  totalQuantity?: number;
  expireDate?: string;
  notes: string = '';
  extra: Record<string, string> = {};
  attachments: RemoteManagedFile[] = [];
  updatedAt: string = '';
  isArchived: boolean = false;
  archivedAt?: string;
}
```

以上是目标模型示意，不能直接替换当前代码，直到后端实际字段和 `RemoteManagedFile` 类型完成核验。解码必须通过项目现有 `SupportAPIResponseDecoder`，不能在 DTO 中使用未约束的 `any` 或直接把 `Object` 强转为领域对象。

### 4.10 写入 API 目标实现

建议在 `MedicalWorkflowAPI.ets` 增加明确方法，而不是让页面调用通用 `createResource` 并拼散落字段：

```text
createMedicineBox(payload: MedicineBoxWritePayload)
  → POST /api/v1/medical/resources/?kind=medicine-boxes
  → RemoteMedicineBox.fromJson

updateMedicineBox(id, payload)
  → PATCH/PUT /api/v1/medical/resources/{id}/?kind=medicine-boxes
  → RemoteMedicineBox.fromJson

deleteMedicineBox(id)
  → deleteResource(MEDICINE_BOXES, id)

setMedicineBoxArchived(id, archived)
  → PATCH /api/v1/medical/resources/{id}/?kind=medicine-boxes
  → {is_archived: boolean}
```

HTTP method和 payload 必须以服务端最终契约确认。iOS 的 `MedicineBoxWritePayload` 字段基线为：`member`、`entry_member_id`、`medicine_name`、`medicine_type`、`brand_name`、`dosage_form`、`strength`、`dose_unit`、`total_quantity`、`expire_date`、`notes`、`extra`、`file_ids`。

### 4.11 取消、单飞和生命周期

- 页面 `aboutToAppear` 触发一次首屏加载。
- 页面刷新 action 与首屏 action 使用同一个 in-flight gate；已有加载时不重复发起。
- 视图消失时取消当前页面任务或用 generation 丢弃结果，不能让旧页面回调写入新账号/新成员缓存。
- 个人/家庭模式切换时必须重新建立 ViewModel 状态，不能沿用另一模式的 `memberFilter`。
- 账号切换时由全局会话 generation 清空页面栈，旧 generation 的远端响应不得更新 `HomeViewModel`。
- GET 可按网络层策略合并 in-flight；非幂等 POST 默认不自动重试。
- DELETE/归档失败不做乐观删除；只有收到服务端成功响应后才更新列表。

### 4.12 日志与错误

日志只记录：`mode`、`memberID`、`boxID`、count、operation、request ID 和错误分类。禁止记录药品备注、附件原始 URL、Token、完整 request body 和完整 response。

错误分类目标：

| 分类 | HTTP/服务端待确认 | 页面行为 |
|---|---|---|
| 未登录/会话失效 | 401/业务失效码 | 交给会话层，不在页面显示原始错误 |
| 无成员权限 | 403/权限业务码 | 显示无权限并返回 |
| 参数校验 | 400/422 | 映射到字段或表单错误 |
| 冲突 | 409 或服务端业务码 | 提示刷新后重新编辑 |
| 限流/暂时不可用 | 429/5xx | GET 可按策略重试；写入默认不自动重试 |
| 网络不可用/超时 | 网络层错误 | 保留缓存，显示重试 |
| 空数据 | 2xx + 空数组 | 显示空态，不算错误 |

### 5.6 首页缓存模型

`RemoteMemberCompleteData` 当前已有：

```text
medicineBoxes: RemoteMedicineBox[]
familyMedicineBoxes?: RemoteMedicineBox[]
```

对齐规则：

- `medicineBoxes`：个人/成员药箱投影，随个人列表成功结果回写。
- `familyMedicineBoxes`：家庭汇总投影，只在家庭汇总成功后回写。
- 归档查询结果不得回写活动列表缓存。
- 缓存仅是内存投影，不写 Preferences、文件或数据库。
- `complete-data` 重载时，如果成员 ID 相同且已有家庭药箱缓存，保留已成功加载的家庭投影；账号/成员变化时丢弃旧投影。

### 5.7 药箱与用药计划/处方/记录

| 对象 | 主键 | 关联字段 | 药箱边界 |
|---|---|---|---|
| `RemoteMedicationPlan` | `id` | `medicine_box` | 药箱提供可选库存引用，不生成计划规则 |
| `RemotePrescription` | `id` | 计划的 `prescription` | 药箱可作为处方识别结果落库对象 |
| `RemoteMedicationRecord` | `id` | `plan` | 药箱不生成服用记录 |
| `RemoteManagedFile` | `id` | `file_ids`/attachments | 药箱只维护资源关联，不负责 OSS 生命周期 |

### 5.8 响应解码和字段兼容

Harmony 当前解码器已兼容部分 snake_case/camelCase，如 `medicine_name`/`medicineName`、`updated_at`/`updatedAt`。目标扩展应继续使用同样规则，但不应无限吞掉未知字段：

1. 读取后端正式 snake_case 字段。
2. 仅在已有跨版本事实支持时兼容 camelCase。
3. 缺失可选字段使用明确默认值。
4. 必须字段缺失时记录非敏感字段错误并进入可观察的 DTO decode failure，不把损坏对象伪装成空药品。
5. 不在页面中再次解析原始 `Object`。
