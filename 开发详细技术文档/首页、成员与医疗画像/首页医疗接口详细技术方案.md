### 1.2 后端与后台管理证据

| 契约层 | 真实来源 | 对齐内容 | 禁止行为 |
| --- | --- | --- | --- |
| 客户端 complete-data | `GET /api/v1/medical/members/<member_id>/complete-data/` → `MemberCompleteDataAPI` | Bearer 鉴权、`MemberPermissionGate.require_access`、ETag `etag_max_age=86400`、304、`success_response` 包裹 | 并发拆成多资源列表拼首页；自造 path |
| 客户端成员列表 | iOS 实际走 `GET /api/v1/medical/resources/?kind=members` → 统一资源代理到 `MemberViewSet`；同后端亦注册 `router.register("members", MemberViewSet)` | 字段来自 `MemberSerializer` + 绑定能力投影 | 仅按旧总领文档写死 `/members/` 而不核对统一资源 |
| 模块配置 | `GET /api/v1/medical/resources/?kind=member-module-settings&member_id=`（iOS `listMemberModuleSettings`） | `MemberModuleSettingSerializer` | 在首页自行发明第二套模块开关 |
| 后台管理 | `GET /api/admin/v1/medical-data/users/<user_id>/members/<member_id>/complete-data/` → `AdminMedicalDataMemberCompleteDataView` | **轻量摘要**：分类计数、权限、审计；**不是**客户端同款全量快照 | 把后台 `category_counts` 当成客户端 `RemoteMemberCompleteData` |

**同源结论：** 客户端与后台管理对「成员医疗总览」入口不同、payload 不同，但都落到同一医疗领域数据；HarmonyOS 首页只能消费 `/api/v1/medical/...` 客户端契约。

### 1.4 结论

| 类别 | 项 |
| --- | --- |
| 已对齐（契约层，两端共用后端） | complete-data path、ETag TTL 86400、权限 403/404、成功包裹 `code/msg/data`、排除已归档资源 |
| 已对齐（鸿蒙网络 ETag） | `If-None-Match` / 304 body 合并、list TTL 120s、complete-data TTL 86400、`X-Cache-Max-Age`、真 SHA-256 缓存键、过期条目删除；`SupportBackend` 共享单一 `MedicalWorkflowAPI` |
| 参考端已实现 | 双段式加载、成员选中优先级、complete-data 降级空卡片、列表 patch、家庭药箱字段保留补丁 |

| HarmonyOS 待继续 | Invite/Share/写接口全量、非首页 DTO、列表页 complete-data 注入与单字段 patch；`DefaultMembersRepository` 尚未挂 AppContainer 主路径 |
| 平台差异 | SwiftUI → ArkUI；UserDefaults → Preferences（非敏感）；URLSession → 既有 `SupportNetworkEngine` |
| 不适用 | 后台 admin complete-data；iOS HealthKit 运动健康分支不在本模块范围 |
| 文档纠偏 | iOS 总领文档流程图写 `GET /api/v1/medical/members/`；**代码事实**为统一资源 `GET /api/v1/medical/resources/?kind=members`。HarmonyOS 必须以代码/后端为准 |

## 3. 分层职责与请求链路

### 3.1 分层与依赖方向

```text
HomePage / HomeViewModel (Presentation)
        ↓
LoadHomeMedicalOverviewUseCase / MemberModuleSetupUseCase (Application)
        ↓
MemberContextStore + SelectedMemberIDStore (跨 Feature 上下文)
        ↓
MedicalQueryAPI / MedicalWorkflowAPI / MedicalSyncAPI（Infrastructure API，目录与 iOS 1:1）
        ↓
SupportNetworkEngine / ETagStore / AuthTokenProvider（上游网络模块，不在本页重定义）
        ↓
SparkService /api/v1/medical/...
```

| 层 | 职责 | 禁止 |
| --- | --- | --- |
| Presentation | 触发 load、成员切换、错误 toast、列表 patch 回写、分区显隐 | new HTTP、解析裸 JSON、写 Token |
| Application | 编排成员列表 → 选中 → complete-data → 卡片投影 | 持有 `@State` UI |
| Domain | `HomeDashboard`、`Member`、卡片 Kind | 网络细节 |
| MemberContext | 成员集合、selectedMemberID、账号隔离持久化、变更通知 | 医疗明细聚合 |
| Medical API | path/query/DTO/ETag 策略声明 | UI、业务 toast |

### 3.2 主流程（与 iOS 对齐）

```text
用户进入已登录首页
  → HomeViewModel.loadInitialIfNeeded()
  → load(syncRemote)
  → LoadHomeMedicalOverviewUseCase.execute(session, selectedMemberID, refreshRemoteSnapshot)
      → GET /api/v1/medical/resources/?kind=members
      → 排序（isPrimary 优先，updatedAt 降序）
      → 解析 selected：传入 > Preferences > 首位
      → 若有选中：GET /api/v1/medical/members/{id}/complete-data/（失败 → completeData=null，空卡片）
      → 组装 HomeMedicalOverview
  → 更新 HomeDashboard + MemberContextStore
  → 保留同 memberId 的 familyMedicineBoxes 内存补丁
  → listMemberModuleSettings(memberID)
  → 渲染成员区 / 4 卡片 / 模块区
  → 点击卡片 → 列表页消费 dashboard.medical.completeData
  → 下拉刷新 → 单资源 list → updateMedicalCompleteData 只 patch 对应字段
```

### 3.3 状态机

| 阶段 | 触发 | 输入 | 参与模块 | 成功 | 临时失败/恢复 | 永久失败/清理 | 用户可见状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 未开始 | 冷启动进 Tab | session | HomeVM | — | — | — | `dashboard==null` |
| 全局加载 | `load` | session, selectedID | UseCase, API | dashboard 写入 | — | listMembers 抛错 → toast，保留旧 dashboard | `isLoading=true` |
| 医疗分片 | UseCase 内 | memberID | complete-data | cards+completeData | complete-data 失败降级空卡片 | — | `isLoadingMedical`；成员区可先有 |
| 模块配置 | load 成功后 | memberID | ModuleSetup | settings 排序 | 失败清空 settings | — | 分区显隐按 isEnabled |
| 成员切换 | select / switch | memberID | Context + load | 新 complete-data | syncRemote false/true | — | 卡片与列表缓存换成员 |
| 成员删除 | deleteMember | member | Context | 若删当前则清空 selected 再 load | 删除失败 toast | — | 成员条刷新 |
| 列表 patch | 列表回调 | 单字段 | HomeVM | 仅该字段更新 | 刷新失败保留旧列表 | — | 返回首页仍命中缓存 |
| 登出/切账号 | SessionInvalidation | accountID | Context + Preferences | clear selected | — | 清空内存 dashboard | 回登录；禁止串账号 |

### 3.4 并发与取消

- 同账号首页 `load` 应单飞或 generation 丢弃：旧请求返回时若 `accountID`/generation 不匹配则丢弃。
- `listMembers` 与 `complete-data` **串行**（先成员后快照），禁止为「加速」改成无成员上下文的并行扇出。
- complete-data 使用网络层 ETag（TTL 86400）；`refreshRemoteSnapshot` 在 iOS 当前**未改变请求策略**（保留参数）；HarmonyOS 首期同样保留参数签名，行为与 iOS 一致，不假装已实现强制刷新语义。

## 4. 核心关键技术与实现方案

### 4.1 双段式聚合加载

**目标：** 一次成员列表 + 一次 complete-data，驱动首页卡片与列表首屏。

**iOS 证据：** `LoadHomeMedicalOverviewUseCase.execute`：`listMembers` 失败抛错；`fetchMemberCompleteData` 用 `try?` 降级；卡片固定 4 类。

**HarmonyOS 路径：** `LoadHomeMedicalOverviewUseCase.ets` + `MedicalQueryAPI.ets`；由 `HomeViewModel.load` 调用；错误经既有 `NotificationClient`。

**官方能力：** [发送网络请求（ArkTS）](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/http-request) — 仅经上游 Transport，本模块不直连 `http.createHttp`。需按 API 24 复核。

**本地示例：**

| 路径 | 可借鉴 | 禁止复制 |
| --- | --- | --- |
| `.../agc-template-market-harmonyos-demos-main/LifestyleAndServiceTemplate/Parking/features/tab/home/src/main/ets/viewmodels/HomePageVM.ets` | Tab 首页 VM 拉取与状态分发 | Mock 车场业务、页面内硬编码 endpoint |
| 既有工程 `Projects/Core/Networking/*` | Engine/ETag/Decoder | 在 HomePage 再造一套客户端 |

**伪代码（不可直接粘贴编译）：**

```typescript
// 伪代码 / 职责骨架 — 未在目标工程 assembleHap 验证
async execute(session: UserSession, selectedMemberID: number | null, refreshRemoteSnapshot: boolean): Promise<HomeMedicalLoadResult> {
  const remotes = await this.medicalQueryAPI.listMembers(); // 失败上抛
  const members = sortMembers(remotes.map(toDomain));
  const resolved = resolveSelected(members, selectedMemberID, this.persistence.load(session.accountID));
  let complete: RemoteMemberCompleteData | null = null;
  if (resolved !== null) {
    try {
      complete = await this.medicalQueryAPI.fetchMemberCompleteData(resolved);
    } catch (_e) {
      complete = null; // 降级空卡片，不让首页整体失败
    }
  }
  return { members, selectedMemberID: resolved, medical: { cards: makeCards(complete), completeData: complete } };
}
```

**验收：** 有成员必有有效 selected；listMembers 失败不出现「空成员成功态」；complete-data 失败卡片 count=0。

### 4.2 成员上下文与选中持久化

**目标：** 账号隔离的当前成员；成员 CRUD 后首页可只刷成员条。

**iOS 证据：** `SelectedMemberIDPersisting` 键 `memberContext.selectedMemberID.<accountID>`；`MemberContextStore`；`HomeViewModel.selectMember` → `load(syncRemote:false)`；`switchMemberAndLoad` → `true`；删除当前成员先清空再 load。

**HarmonyOS 路径：** Preferences（或项目 `ProjectKeyValueStore` 门面，见键值存储方案）存选中 ID；登出/切账号 `clear(accountID)`。

**官方能力：** [Preferences（ArkData）](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/data-persistence-by-preferences) — 仅非敏感偏好；需按 API Level 复核。

**本地示例：** LiveStreaming `PreferenceUtil` — 可借鉴 get/put/flush；**禁止**打印 value、存 Token。

**安全：** 选中成员 ID 非密钥，但必须账号 scope；禁止写入 ETag body 以外的明文医疗快照到 Preferences（complete-data 保持内存态，与 iOS 一致）。

### 4.3 Complete-data 与首页缓存补丁

**目标：** 高复用聚合快照；家庭药箱仅按需回写。

**iOS 证据：** `fetchMemberCompleteData` path + `etagTTL: 86400`；`HomeViewModel.load` 在同 `memberId` 时保留上一份 `familyMedicineBoxes`；`updateMedicalCompleteData` 闭包式字段 patch。

**后端事实：** 响应 **不含** `family_medicine_boxes`；含 `member_id/member/member_medical_profile/member_module_settings/nutrition_goal_state/medical_cases/.../follow_ups`（见第 5 节）。ETag 计算还纳入 exam_plans 等，但 **payload 未返回这些字段** — 客户端不得臆造。

**HarmonyOS：** 内存态挂在 `HomeDashboard.medical.completeData`；列表页注入同一引用；patch 必须字段级，禁止整对象盲目覆盖导致丢失 familyMedicineBoxes。

### 4.4 模块配置与分区显隐

**目标：** 按当前成员 `isEnabled` 决定医疗/饮食分区或模块维护入口。

**iOS 证据：** `loadCurrentMemberModuleSettings`；`shouldShowMedicalSection` / `Nutrition` / `ModuleMaintenance`；complete-data 已含 `member_module_settings`，但首页仍二次请求（已知缺口，见第 9 节）。

**HarmonyOS 首期：** 与 iOS 行为对齐（二次请求），避免提前「优化」导致与参考端验收不一致；优化列为演进项。

### 4.5 列表页首屏复用与局部刷新

**目标：** 首屏不重拉 complete-data；下拉只刷当前资源并回写。

**iOS 证据：** `HomeMedicalRouteSupport` 注入；`ExaminationReportsListPage.refreshReports` 只调检查报告 list 并 patch `examinationReports`。

**HarmonyOS：** 路由参数携带 `memberID` + 由 HomeVM 提供 completeData 读取/patch 回调；Navigation 复用主 Tab 栈，遵守上游「禁止嵌套业务 Navigation」规则。

**官方能力：** [Navigation 与路由](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-navigation-navigation) — `NavDestination` 唯一根；需按 API 24 复核。

### 4.6 装配与日志

- 在 `AppContainer` / Feature Assembly 注入 `MedicalQueryAPI`、`MemberContextStore`、`LoadHomeMedicalOverviewUseCase`。
- 日志用既有 `Logger` + `LogModule.home` 语义；只记 accountHash/memberID/cost/cards.count；禁止完整 complete-data body、附件 URL 批量、Token。

### 5.3 数据模型对齐原则（强制与 iOS 一致）

客户端医疗数据模型以 iOS `SparkMedicalSyncAPI`（`MedicalSyncAPI.swift`）为**唯一命名与字段语义基线**；JSON wire 名以 SparkService Serializer / `MemberCompleteDataAPI` payload 为准。HarmonyOS 不得另起一套字段名。

| 规则 | iOS 事实 | HarmonyOS 要求 |
| --- | --- | --- |
| 命名空间 | `SparkMedicalSyncAPI.Remote*` | 对等类名：`RemoteMember`、`RemoteMemberCompleteData` 等（放 `MedicalSyncAPI.ets`，与 iOS 同文件名） |
| JSON ↔ 属性 | `JSONDecoder.keyDecodingStrategy = .convertFromSnakeCase`：`member_id` → `memberId` | **禁止**依赖隐式转换；每个 DTO 显式 `fromJson`/`toJson`，wire 键保持 snake_case |
| 日期 | `MedicalDateCoding`（日期-only / ISO8601） | 同语义解析函数；失败 → `null`，不抛整包失败（与列表容错一致处除外） |
| 缺省布尔 | `@DefaultFalse` → 缺省 `false` | `is_archived` 等缺键默认 `false` |
| 空对象 | `@EmptyObjectAsNil`（smoking/drinking/exercise profile） | `{}` 解码为 `null` |
| 领域映射 | `RemoteMember` → `Member` + `MemberBindingInfo` | 同字段映射表；`effectiveBinding` 无 binding 时用受限 fallback |
| 禁止 | — | 把后台 admin complete-data 字段、Swift 展示文案、本地化 key 写进 DTO |

### 5.9 解码与实现约束（HarmonyOS）

1. complete-data / Remote* 放在 `MedicalSyncAPI.ets`；其余请求/响应按 **§5.10** 分文件放置（与 iOS 同名）；禁止另建 `MedicalSyncModels.ets`。
2. 每个类提供 `static fromJson(json: object): T` 与必要的 `toJson()`；**禁止** `as Record`、indexed access、隐式 any。
3. `extra` / `detail_data` / `allergy_details` / `meal_distribution` 使用显式 map 类型与遍历 helper，不在业务层动态索引。
4. complete-data 整包解码失败才算失败；单字段非法优先跳过/置默认（与 iOS 容错策略冲突时以「不丢整包」为先，并记测试）。
5. 列表 patch 只替换上表对应数组字段，不得 `Object.assign` 整包覆盖导致丢失 `family_medicine_boxes`。

```text
┌──────────────────────────────────────┐
│  首页                          [刷新] │
├──────────────────────────────────────┤
│  成员条：[本人 ▼]  [+]               │  ← 点击切换成员 → selectMember

│  └─────────┘ └─────────┘             │
│  ┌─────────┐ ┌─────────┐             │
│  │ 检查  n │ │ 用药  n │             │
```

| --- | --- |
