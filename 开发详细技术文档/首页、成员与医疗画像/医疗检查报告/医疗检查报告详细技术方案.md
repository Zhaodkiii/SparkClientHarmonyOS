### 1.2 后端与后台管理证据（单一契约源）

| 契约层 | 真实来源 | 必须对齐 |
| --- | --- | --- |
| 路由 | `SparkService/medical/urls.py` | `router.register("examination-reports", ExaminationReportViewSet)`；`med-exam-details` ViewSet；统一门面 `resources`；`POST workflows/medical-reports/create/`（`MedicalReportWorkflowSaveView`） |
| 模型 | `medical/models.py` → `ExaminationReport`、`MedExamDetail` | Source 1–2；Status 1–4；`MedExamDetail.BusinessType.EXAMINATION_REPORT="examination_report"` |
| Serializer | `ExaminationReportSerializer`、`MedExamDetailSerializer` | 字段表见 §5；读出时 `raw_ocr` 被 `to_representation` pop |
| 工作流 | `MedicalReportWorkflowSaveView` | 原子保存报告 + details（`business_type=examination_report`）+ `file_ids` 绑定 |
| 权限 | Serializer `validate_member` | 非 staff 须有 active binding；`medical_record.member` 须与报告 member 一致 |
| 响应包裹 | `common/response.success_response` | `{code,msg,data}`；create 返回 `data.id`（及 report/details） |
| 后台管理 | admin medical-data complete-data | **另一套摘要 payload**，禁止当客户端契约 |

**同源结论：** 客户端只消费 `/api/v1/medical/...`；不得新增平行 path 或改写 `business_type`。Examination vs HealthExam 在后端是两套 ViewSet / 两套 workflow，**禁止混用** `health-exam-reports` 与 `examination-reports`。

### 1.3 参考端与目标端

- **参考端：** `SparkClient`；总领 `医疗检查报告.md`（流程第三～九节；UI/模型见 **§二点五**）。
- **目标端：** `SparkClientHarmonyOS`；list + patch 已通；深度 UI / 三类卡片 / 明细 / 写链路 / OCR 待实现。
- **目标用户能力：** 查看当前成员检查列表（缓存首屏）、分类筛选与时间线、下拉刷新、归档切换；懒加载明细后进详情；手工新建 / 上传识别入库；删除/归档/分享（与 iOS 可观察行为对齐）。

### 1.4 结论

| 类别 | 项 |
| --- | --- |
| 已对齐（契约/设计） | kind=`examination-reports`；资源 business=`examination_report`；列表 refresh + 活跃 patch；归档不回写活跃缓存；首页卡 Kind.`medicalReports` → 路由 `home.medical.examination` |
| HarmonyOS **部分实现** | 共用列表壳标题行 + `listExaminationReportsWithAttachments` + `patchExaminationReports`；DTO **无**明细；通用 `listMedExamDetails` 已有但检查未挂 |
| HarmonyOS **待实现** | `ExaminationReports` 独立目录、`LabReportCard`、三类详情、检查侧明细懒加载、`saveMedicalReport` / mutation、OCR、分享、Chat |
| 平台差异 | 列表导航用 `Navigation`/`NavDestination`（API 24）；禁止嵌套业务 Navigation；上传 Sheet/相机走 PhotoAccessHelper/Camera Kit（权限声明后） |
| 不适用 | 把检查做成体检分类页；把 `health_exam_report` 明细当检查明细；把 ExamArchive 主流程算作本模块完成标准 |
| 已知 iOS 实现 quirks（跨端须知情） | **实验室单条子项**当前路由到 `ImagingReportDetailPage`（实验室分支被注释）；完整检验宽表仍走 `LaboratoryReportDetailPage`（见 iOS §二点五·2.5.1） |

### 2.6 项目架构原则与依赖方向（强制 · 对齐 iOS §2.3）

```text
Home 卡片 Kind.MEDICAL_REPORTS（命名历史 medicalReports）
  → NavPathStack push(home.medical.examination)
  → ExaminationReportsListPage（目标）/ HomeMedicalListPage（当前壳）
      → MedExamDetailLazyLoad*（列表态；business_type=examination_report）
      → ExamReportForm / MedicalDocumentUpload（写入 · 待）
      → ExaminationReportDetailHost → Summary / Lab / Imaging / Pathology
          → ExaminationReportServerMutationService → WorkflowAPI
      → MedicalQueryAPI（刷新 / 明细）
  → onExaminationReportsUpdated
      → HomeMedicalRouteSupport.patchExaminationReports
          → HomeViewModel.updateMedicalCompleteData { examinationReports = … }
```

**架构对齐原则：**

1. **无独立 ExaminationReport Repository**；查询走 `MedicalQueryAPI`，写入走 `MedicalWorkflowAPI` / MutationService（与 iOS 同）。  
2. **列表/详情主存 = `RemoteExaminationReportWithAttachments`**；Domain `ExaminationReport` 若落地仅作映射，不作 UI 权威。  
3. **懒加载与体检共用协议、分 `business_type`**；禁止把 `health_exam_report` 明细挂到检查报告。  
4. **权威缓存唯一**：HomeVM `completeData.examinationReports`；禁止 Disk/Preferences 持久化检查快照。  
5. **归档列表 `onReportsUpdated = null`**，切断活跃缓存污染。  
6. **页面禁止** `http.createHttp()`；一律经 Network Engine。  
7. **目录命名镜像 iOS** `ExaminationReports/` + `LabReportCard`；勿并入 `HealthExamReports/`。

## 3. 分层职责与请求链路

### 3.1 分层职责（Presentation / Application / Domain / Infra）

| 层 | 职责 | 不做 |
| --- | --- | --- |
| Presentation | 列表/三类卡片/详情 UI；Chip/搜索/时间线；归档切换；触发刷新/上传/手工新建 | 拼 path、持有权威缓存、编解码 JSON |
| Application（共享） | 明细懒加载单飞；表单/上传编排（待） | HTTP path 字符串；第二套缓存 |
| Domain | 可选实体映射；`ExaminationReportCategory` 枚举与匹配启发式 | UI 布局 |
| Infrastructure API | Query/Workflow/Share DTO 编解码 | 页面 `@State` |
| 缓存接线 | RouteSupport 单字段 patch | 重算首页 cards（已知缺口另记） |

### 3.2 整体业务流程（对齐 iOS §2.5.7 / §十 · 阶段 0–6）

```text
阶段0 首页聚合
  listMembers → 选中成员 → fetchMemberCompleteData
  → completeData.examinationReports（通常无 medExamDetails）
  → 卡片 count / latestDate 投影

阶段1 进列表首屏
  点击 Kind.medicalReports → push examination
  活跃：hydrate completeData.examinationReports（零二次 complete-data）
  归档：初始 [] → .task list(archived=true)；onReportsUpdated=null

阶段2 明细懒加载
  LabReportCard 可见 → medExamDetails==null → listMedExamDetails
  （business_type=examination_report；accepted 兼容 examination）
  成功整表 onReportsUpdated → 活跃 patch；失败仅 log，保持 nil 可重试

阶段3 下拉/按钮刷新
  listExaminationReportsWithAttachments
  活跃 patch；失败 toast 保留旧表；刷新后明细常清空 → 再懒加载

阶段4 进详情
  「查看详情」门禁：medExamDetails?.isEmpty == false
  → SummaryDetail；实验室「完整表」→ Laboratory；子项行 → Imaging/Pathology
  （iOS quirk：实验室单行当前 → Imaging）

阶段5 Mutation
  编辑：头 update → list 旧明细 → delete 匹配 business_type → create 新行
  删除/归档：Workflow → remove/upsert → 活跃 patch；归档页不回写首页

阶段6 OCR / 手工新建
  手动添加 → ExamReportForm → prepend + patch
  上传 → documentKind=medicalReport → RecognitionDraft → workflows/medical-reports/create/
```

### 3.3 页面跳转与缓存副作用（对齐 iOS §2.5.3）

```text
Home 卡片 medicalReports
  → ExaminationReportsListPage(active, patch examinationReports)
toolbar「归档」
  → ListPage(archived, onReportsUpdated:nil)
LabReportCard.task → loadDetails → patch（活跃）
「查看详情」→ DetailHost → Summary
  ├─ 完整检验表(实验室) → LaboratoryReportDetailPage(全量)
  └─ 子项行 → Imaging(实验室当前/影像) | Pathology
手动添加 / 上传 → Form / OCR → prepend|refresh → patch
病历时间线（旁路）→ upsert 单条 examinationReports
```

| 跳转 | 缓存副作用 |
| --- | --- |
| 活跃懒加载 / 刷新 / CRUD upsert | `patchExaminationReports` → `completeData.examinationReports` |
| 归档列表一切操作 | **不**回写首页活跃数组 |

## 4. 核心关键技术与实现方案

### 4.0 项目架构对齐（强制）

| 原则 | iOS 事实 | HarmonyOS 要求 |
| --- | --- | --- |
| Features 层目录 | `MedicalLists/ExaminationReports/` + Shared LazyLoad | **同名目录**；检查勿并入 `HealthExamReports/` |

### 4.1 列表首屏与缓存消费（部分实现）

1. **目标：** 活跃列表零二次 complete-data 请求直出。  
2. **iOS：** `ExaminationReportsListPage` 初始化吃 `completeData.examinationReports`（见总领第三节 / §二点五·2.5.7）。  
3. **HarmonyOS 当前：** `HomeMedicalListPage.hydrateFromCache` → `applyExam` **只抽标题字符串**；刷新走 `listExaminationReportsWithAttachments` + `patchExaminationReports`。  
4. **目标实现：** 独立 `ExaminationReportsListPage` 持有 `RemoteExaminationReportWithAttachments[]`；归档模式 `onReportsUpdated=null`。  
5. **官方：** [Navigation](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-basic-components-navigation) — `NavPathStack` + `navDestination`；目的地 Builder 必须以 `NavDestination` 为唯一根；按 API Level **24** 复核。  
6. **本地示例（结构）：** Parking `HomePageVM`（仅借鉴 VM 聚合首页状态 / `Promise.allSettled` 并行拉数结构，**禁止**复制业务 Https/车牌逻辑）。路径：  
   `开发详细技术文档/agc-template-market-harmonyos-demos-main/LifestyleAndServiceTemplate/Parking/features/tab/home/src/main/ets/viewmodels/HomePageVM.ets`  
7. **验收：** 有缓存进页不发 complete-data；归档操作不污染活跃 `examinationReports`。

### 4.2 三类分类、筛选与时间线（待实现）

1. **目标：** `ExaminationReportCategory`：`laboratory` / `imaging` / `pathology`；Chip + 搜索纯本地；时间线按 `reportedAt ?? performedAt` 排序后**相邻同分类合并**。  
2. **匹配优先级：** 标准字面 → 摘要关键词 → **兜底实验室**（见 iOS §二点五·2.5.1）。  
3. **搜索字段：** `itemName`、`category`、`subCategory`、`organizationName`、`departmentName`、`doctorName`、`findings`、`impression`。  
4. **勿与体检混淆：** 体检筛选是「有综述/有附件」等，不是实验室/影像/病理。

### 4.3 明细懒加载（待实现 · 检查链路）

1. **目标：** `medExamDetails == null`（或未加载标记）才请求；同 ID 单飞；成功活跃 patch。  
2. **iOS：** `MedExamDetailLazyLoadViewModel`；`business_type=examination_report`；accepted 含 `examination`（见总领第五节 / §二点五·2.5.7）。  
3. **HarmonyOS 阻断：**  
   - `RemoteExaminationReportWithAttachments` **尚无** `medExamDetails`；  
   - `listMedExamDetails` **方法已有**，但检查列表/卡片未调用；  
   - 无检查侧 LazyLoad 控制器（仅有体检 `HealthExamDetailLazyLoadController`）。  
4. **并发：** `loadingIDs` Set；失败保持未加载可重试；失败不弹阻塞 toast（对齐 iOS）。  
5. **异常启发式：** 列表统计用 `flag`（`isPotentiallyAbnormal`：高/低/异常/阳性/abnormal/…）；与体检共用启发式工具时可复用 `HealthExamFlagSupport`，但 **business_type 不得串**。

### 4.4 下拉刷新与字段 patch（部分实现）

1. **API：** `GET /api/v1/medical/resources/?kind=examination-reports&member_id=&archived=`（与现有 `MedicalQueryAPI` 一致）。  
2. **活跃：** `HomeMedicalRouteSupport.patchExaminationReports`；**归档：** 不 patch。  
3. **失败：** `NotificationClient.error`；不写空数组覆盖缓存。  
4. **副作用：** 列表刷新后明细通常清空，目标态需再次懒加载。

### 4.5 工作流保存 / 删除 / 归档 / 分享（待实现 · mutation）

1. **OCR / 类型化保存：** `POST /api/v1/medical/workflows/medical-reports/create/`  
   - body：成员、分类/项目名、所见印象、日期、details[]、file_ids[] 等（服务端双读 snake/camel；影像/病理 impression 可拼 details.diagnosis）  
   - 成功：`data.id`（及 report/details）；`business_type=examination_report` 绑定明细与附件。  
2. **手工新建 / 编辑：** iOS 走统一资源 create/update + 明细全量替换（list 旧 → delete → create）；HarmonyOS 对齐同一语义，禁止只改头不清明细。  
3. **Delete：** `DELETE /api/v1/medical/resources/{id}/?kind=examination-reports`（可复用已有 `deleteResource`）。  
4. **Archive：** PATCH `is_archived`；kind=`examination-reports`（需补检查专用或通用 setArchived）。  
5. **Share：** `business_type=examination_report`。  
6. **HarmonyOS 现状：** **无** `saveMedicalReport`；体检 save/archive 已有但**禁止**复用到检查。  
7. **官方 HTTP：** [发送网络请求（ArkTS）](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/http-request) — 经项目 Network Engine，禁止页面直连。  
8. **安全：** 不把 `raw_ocr`、附件 URL、Token、所见/诊断全文打进 hilog；Preferences 不存报告正文。

### 4.6 上传识别（待实现 · OCR）

- 文档 kind：`.medicalReport`（对齐 iOS）；底部 **手动添加 + 上传**（异于体检仅「拍摄添加」teal）。  
- 识别草稿：`MedicalReportRecognitionDraft`；落库走 `MedicalReportWorkflowSaveView` 或统一资源路径。  
- 本模块只定义入口契约；OCR/OSS 细节引用上游文件与 OCR 方案。  
- **禁止**走病历组合包创建路径冒充检查报告主流程；**禁止**调用 `health-exams/save/`。
