### 1.2 后端与后台管理证据（单一契约源）

| 契约层 | 真实来源 | 必须对齐 |
| --- | --- | --- |
| 统一资源路由 | `SparkService/medical/unified_resources.py` → `"member-module-settings"` | `GET/POST/PATCH /api/v1/medical/resources/?kind=member-module-settings&member_id=`[+`module_code`] |
| 直连 ViewSet | `medical/urls.py` → `member-module-settings`；`MemberModuleSettingViewSet` | POST create 实为 `update_or_create`；PATCH 按 id |
| 模型 | `MemberModuleSetting`（`ModuleCode`: `medical` / `nutrition` / `daily_health`） | `is_enabled` 模型默认 `True`；客户端首页显隐仍以**返回行的 is_enabled**为准 |
| Serializer | `MemberModuleSettingSerializer` | 字段见 §5；`validate_member` 须 active binding |
| complete-data | `MemberCompleteDataAPI` 含 `member_module_settings` | 首页**当前仍二次 list**（与 iOS 同缺口） |
| 后台管理 | admin medical-data / Django Admin | **不可**当客户端契约；client 只走 `/api/v1/medical/...` |

**同源结论：** path / kind / JSON 字段名以 SparkService 为准；禁止自造平行 endpoint 或第二套开关语义。

### 1.3 参考端与目标端

- **参考端：** `SparkClient`；总领《首页成员模块》（切换、分区、SetupFlow、API、缺口清单）。

### 2.6 项目架构原则与依赖方向（强制）

**分层依赖方向（与 iOS 一致）：**

```text
Presentation（HomeTab 成员条 / SetupFlowPage / 未来 MemberDetail）
        ↓
Application（LoadHomeMedicalOverview / MemberModuleSetup / ManageHomeMember）
        ↓
MemberContext（Store + SelectedMemberID 持久化）—— 不持有 module settings 权威
        ↓
Infrastructure API（Query list/create/update · Sync DTO）
        ↓
Core Networking Engine → /api/v1/medical/...
```

**原则：**

1. **无第二缓存真相：** 首页分区权威源 = `HomeViewModel.currentMemberModuleSettings`（二次 list）；complete-data 内 settings **当前不**当权威；旁路 `moduleSetupCache`（若补）仅服务 Setup 维护流，**禁止**当首页缓存。  
2. **无页面直连 HTTP：** SetupFlow / HomeTab 禁止 `http.createHttp()`。  
3. **写路径单一 kind：** upsert 只走 `member-module-settings`；禁止平行 endpoint。  
4. **显隐只认 `is_enabled`：** `is_completed` / `section_progress` **不参与**首页分区显隐。  
5. **安全：** `summaryText` / `extra` 可能含健康摘要 → 日志只记 memberId/count/code；选中 ID 可进 Preferences，禁止 Token/健康快照进 Preferences。

```text
HomeTabPage
  → HomeViewModel.selectMember | switchMemberAndLoad | load
      → MemberContextStore（选中持久化）
      → LoadHomeMedicalOverviewUseCase（listMembers + complete-data）
      → MemberModuleSetupUseCase.loadModuleSettings
          → MedicalQueryAPI.listMemberModuleSettings
      → shouldShowMedical / Nutrition / ModuleMaintenance

HomeTab 「+」→ push home.member.setup.create
HomeTab 维护 → push home.member.setup.maintain
  → MemberSetupFlowPage(.create | .maintain)
      → ManageHomeMemberUseCase.create（create 流）
      → MemberModuleSetupUseCase.saveModuleSetting / mark*
          → Query create/update kind=member-module-settings
      → onFinished → selectMember +（可选）applyModuleSettings
```

## 4. 核心关键技术与实现方案

### 4.1 模块配置读闸门（已落地）

1. **目标：** 医疗主路径成功后，单独 list settings，作为首页分区权威源（内存）。  
2. **iOS 证据：** `HomeViewModel.loadCurrentMemberModuleSettings` → `MemberModuleSetupUseCase.loadModuleSettings`；失败清空 + warning、无 toast。  
3. **HarmonyOS：** 同名链路；UseCase 按 `displayOrder` 排序。  
4. **官方能力：** 网络走既有 Engine（[发送网络请求（ArkTS）](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/http-request)，API 24 复核）。  
5. **本地示例：** LiveStreaming Token/Preferences — 只借鉴拦截器边界；**禁止**全量 body 日志。  
6. **验收：** Charles 可见二次 GET `kind=member-module-settings`；失败后 settings 为空且有 warn。

### 4.2 分区显隐与 default-off（已收敛）

1. **目标：** `shouldShowMedicalSection` / `Nutrition` / `ModuleMaintenance`。  
2. **iOS：** 「默认不开通」——仅当存在 `isEnabled == true` 的配置行才展示；空数组 → 均 OFF → 有选中则维护卡。  
3. **HarmonyOS 代码事实（当前）：**

```text
isModuleEnabled(moduleCode):
  遍历 settings：同 moduleCode 且 isEnabled → true
  否则 false
  // 空数组 / 失败清空 → OFF（对齐 iOS；注释写明「默认不开通」）
```

4. **历史：** 早期曾对空数组默认 medical ON；**当前已删除该分支**。文档与矩阵不得再写「鸿蒙 default-on」为现状。  
5. **连带：** settings list 失败 → `[]` → 误显**维护卡**（与 iOS 同向）；无 toast。  
6. **UI 初值：** `HomeTabPage.showMedical = false`，避免首帧闪医疗区。

### 4.3 成员切换与选中持久化

1. **目标：** 账号隔离恢复上次选中；切换驱动 complete-data + settings。  
2. **iOS：** chips → `selectMember`；推送 → `switchMemberAndLoad`；UserDefaults key `memberContext.selectedMemberID.<accountID>`。  
3. **HarmonyOS：** `SelectedMemberIDStore` + `MemberContextStore`；**chips 走 `selectMember`**（已对齐主路径）。  
4. **官方：** [Preferences](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/data-persistence-by-preferences) — 非敏感元数据；登出须 `clearForAccount`。  
5. **验收：** 杀进程同账号恢复选中；切账号不串 ID；`reloadMembers` 不偷偷刷新 settings。

### 4.4 MemberSetupFlow / upsert（部分实现）

1. **目标：** create（默认开通 medical）与 maintain（勾选 medical/nutrition、可选 section_progress）。  
2. **iOS 证据：** `MemberSetupFlowView` / `ViewModel`；`saveModuleSetting` upsert；`finish` **从不写 isEnabled=false**。  
3. **HarmonyOS 当前：**  
   - UI：`MemberSetupFlowPage` 四步（nameBirth → birthDate → relationship → modules）；maintain 直达 modules。  
   - 写：`MemberModuleSetupUseCase.saveModuleSetting` → list 同 module_code → update 或 create。  
   - create：`ManageHomeMemberUseCase.create` → `enableDefaultMedicalModuleForCreatedMember`。  
   - **缺：** Medical/Nutrition 汇总子目录、Lifestyle、旁路 cache、模块行点击进引导。  
4. **导航：** Tab 内 `Navigation` 栈 push；禁止嵌套业务 `Navigation`。[组件导航 Navigation](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-navigation-navigation)（API 24）。  
5. **本地示例：** HomeDecoration 表单 — 借交互骨架；禁 Mock 业务数据。

### 4.5 与 complete-data / 缓存边界

- 权威首页分区源：`HomeViewModel.currentMemberModuleSettings`（二次 list）。  
- complete-data 内 `memberModuleSettings`：可演进优先消费；**当前不得**当已优化完成。  
- `moduleSetupCache`（iOS 维护旁路）：鸿蒙**未发现**；属 Setup 旁路，**非**《首页医疗数据缓存》权威源。  
- Setup 写回后可用 `applyModuleSettings` 立即刷新分区，避免等完整 load。

### 4.6 安全与并发

- `summaryText` / `extra.section_progress` 可能含健康摘要 → 日志只记 memberId/count/code。  
- `loadGeneration` 丢弃过期 load；`selectMember` 快速连点需回归。  
- upsert 须单飞 `isPersistingModules`；写接口默认不自动重试。
