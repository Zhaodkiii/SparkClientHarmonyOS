# SupportClientHuawei｜账户管理详细技术方案

## 1. 对标范围与结论

- **后端与后台管理证据：** 本次未给出 `SparkService` 后端工程，无法核验服务端 `urls/view/serializer/service/permission/test`；当前只能以 iOS 与 HarmonyOS 客户端已落地 API path 作为消费事实，后端字段、业务码、后台管理同源关系均标记待确认。
- **参考端与证据：** iOS `SupportClient/SupportClient/Projects/Features/AccountManagement/`、`Projects/Features/Settings/Presentation/SettingsView.swift`、`Projects/Core/Networking/API/Account/AccountIdentityAPI.swift`、`Projects/Core/Networking/API/Account/DeactivationAPI.swift`、`Projects/Core/Networking/API/Auth/OTPAPI.swift`、`总领文档/设置与账户管理/账户管理需求.md`。
- **HarmonyOS 目标端与现状：** `SupportClientHuawei` 目标 SDK `6.1.1(24)`；已落地账户管理 Domain/Application/Infrastructure/Presentation（P1–P6）、设置正式/游客分流、typed AccountIdentity/Deactivation DTO、专项单测；Huawei 账号仅 UI ComingSoon；**未做 P7** 真机/SparkService 联调。
- **目标用户能力：** 正式账号进入账户管理，查看账号资料与登录方式，完成手机号/邮箱身份绑定或换绑，执行退出登录和账号注销；游客账号入口打开升级登录；Huawei 账号展示即将支持。
- **结论：** 华为端账户管理 **P1–P6 已对齐可编译交付**：资料/身份列表、绑定换绑状态机、注销确认、退出确认与本地登出、资源键与单测齐全。Apple 不实现；Huawei Account Kit 真绑定与后端业务码全表验收仍属 R1/R2/P7。

## 3. 分层职责与请求链路

| 阶段 | 触发 | 输入 | 参与模块 | 成功 | 临时失败/恢复 | 永久失败/清理 | 用户可见状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 设置入口 | 点击设置页账户行 | `UserSession` | `SettingsPage`、`AppSessionStore`、`Navigation` | 正式账号进入账户管理，游客打开升级登录 | 会话尚未准备时禁用入口或显示 loading | signedOut 时回登录 | 账户行摘要、sheet 或账户页 |
| 资料/身份加载 | 账户页 `aboutToAppear` 或 ViewModel 初始化 | `UserSession`、`bundleId` | ViewModel、UseCase、Repository、`AccountIdentityAPI` | 展示账号资料与身份列表 | 网络失败可重试 | 401 明确失效清理会话 | loading、资料卡、错误提示 |
| 身份绑定/换绑 | 点击身份行绑定/修改 | provider、operation | 身份状态机、OTP API、AccountIdentity API | 更新身份列表 | OTP 失败停留原步骤 | verification ticket 失效需重走再验证 | 再验证、目标输入、完成态 |
| 注销 | 点击危险区注销 | 注销选项、verification | 注销状态机、OTP/API、Deactivation API、SignOut | 提交注销并切 signedOut | OTP/提交失败可回退重试 | 成功后清理本地会话和账号数据 | 确认短语、提交中、回登录 |
| 退出登录 | 点击退出登录 | 当前会话 | `SignOutUseCase`、`AppLifecycleCoordinator`、`AppSessionStore` | 清理会话并回 signedOut | 本地失败记录日志并仍执行 UI 清理需谨慎 | Token 清理失败需告警 | 确认弹窗、回登录 |

目标请求链路：

```text
SettingsPage / AccountManagementPage
  ↓
AccountManagementViewModel
  ↓
Application UseCase
  ↓
AccountManagementRepository
  ↓
SupportBackend.accountIdentity / otp / deactivation / AuthRepository
  ↓
SupportNetworkEngine
  ↓
HTTP / Token / Retry / 401 / Request ID
  ↓
领域模型映射、flow state 更新、NotificationClient 反馈
```

取消与并发规则：

- 资料与身份列表可并发加载，但账号切换 generation 不匹配时必须丢弃旧结果。
- 再验证和目标 OTP 各自保留 sending flag，防止重复发码。
- `verificationTicket` 只存在内存中，不持久化；流程取消、完成或失败退出时清空。
- 注销提交为非幂等写请求，客户端默认不重试；必须禁用重复提交，并待后端确认是否支持 idempotency key。

## 4. 核心关键技术与实现方案

### 4.1 设置入口与页面导航

目标：保持设置页作为账户管理唯一入口。正式账号进入账号管理页；游客账号打开升级登录 sheet。HarmonyOS 已用 `Navigation`、`NavPathStack`、`bindSheet` 建立 Settings 二级导航。

iOS 证据：`SettingsView.swift` 中 `onAccountEntryTap`，`AppCoordinatorView.swift` 中 `handleAccountEntryTap()` 按 `session.isDeviceAccount` 分流。

HarmonyOS 实现路径：

- 保留 `SettingsPage.ets` 的 `Navigation(this.settingsStack)`。
- 将 `settings_account` 行改为读取 `AppContainer.shared()?.sessionStore.currentSession`，正式账号 push `account.management`，设备游客打开 `showUpgradeSheet`。
- 账号摘要显示 `displayName`、`email/contact` 或“未登录”。
- 账号切换、登出时调用 `clearLocalNav()`，同时清空账户管理 ViewModel 状态。

官方资料：

- `Navigation - 文档中心`：`https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V5/arkts-navigation-navigation-0000001885999037-V5`，用于 `Navigation` / `NavPathStack` 路由设计，需按 API 24 复核。
- `UIContext / OverlayManager`：`https://developer.huawei.com/consumer/cn/doc/harmonyos-references-v5/js-apis-arkui-uicontext-V5`，用于复杂弹层或 `bindSheet` 能力边界，需按目标 SDK 复核。

本地示例：

- `.../HouseAndHomeTemplate/RentAndBuy/components/aggregated_login/src/main/ets/viewmodel/AggregatedLoginVM.ets`：可借鉴登录弹层状态管理；禁止复制第三方登录 SDK、示例账号和硬编码 AppId。
- `.../ShoppingTemplate/Express/components/aggregated_login/src/main/ets/utils/LoginSheetUtils.ets`：可借鉴半屏登录容器；禁止把组件级工具变成全局业务路由器。

### 4.2 账号资料与身份列表

目标：进入账户管理页后展示本地会话资料与远端登录身份列表。账号资料来自 `UserSession`；身份列表来自 `/api/v1/accounts/identities/`。

iOS 证据：`AccountManagementViewModel.load(session:)` 并发调用 `LoadAccountProfileUseCase` 与 `LoadAccountIdentitiesUseCase`；`DefaultAccountManagementRepository.loadAccountProfile` 从 `UserSession` 构造 `AccountProfile`。

HarmonyOS 实现路径：

- 新增 `AccountProfile`、`AccountIdentityStatus`、`AccountIdentityList` 领域模型。
- `LoadAccountProfileUseCase` 仅从 `UserSession` 映射，不发网络。
- `LoadAccountIdentitiesUseCase` 通过 Repository 调 `backend.accountIdentity.listIdentities(bundleId)`。
- `IdentityStatusDTO.provider` 只允许已确认 provider；未知 provider 不进入 UI，但记录脱敏日志。

官方资料：

- `发送网络请求（ArkTS）`：`https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/http-request`，用于 HTTP 请求、权限与关闭行为；当前项目已由 `SupportNetworkTransport` 封装。
- `HTTP错误码`：`https://developer.huawei.com/consumer/cn/doc/harmonyos-references/errorcode-net-http`，用于区分网络层错误与业务错误。

本地示例：

- `.../LiveStreaming/commons/utils/src/main/ets/network/interceptor/JsonResponseInterceptor.ts`：可借鉴集中 JSON 解析思想；禁止复制其 ArrayBuffer 限制和生产日志策略。
- `.../NewsTemplate/News/commons/network/`：可借鉴独立网络模块边界；当前项目已在 `Projects/Core/Networking/` 落地，无需再拆新 HAR。

### 4.3 身份绑定、换绑与高风险再验证

目标：手机号、邮箱、Huawei 账号等 provider 的绑定/换绑必须先完成已绑定身份再验证，拿到 `verificationTicket` 后再提交目标身份。

iOS 证据：`AccountIdentityFlowState`、`RequestIdentityVerificationUseCase`、`VerifyIdentityVerificationUseCase`、`BindAccountIdentityUseCase`、`ChangeAccountIdentityUseCase`；手机号/邮箱使用 OTP，Apple 使用系统授权凭证。

HarmonyOS 实现路径：

- 把 iOS 的 `.apple` provider 替换为待产品确认的 `huawei` 或后端确认 provider；不能把 Apple 凭证流程照搬到 HarmonyOS。
- 新增 `AccountIdentityFlowState.ets`，状态至少包含 `idle`、`choosingReauth`、`reauthOTP`、`reauthProvider`、`enteringTarget`、`targetOTP`、`submitting`、`completed`、`failed`。
- 手机号使用 E.164 目标快照，邮箱使用 normalized email；目标 OTP 发出后冻结 target，重发与提交均使用冻结值。
- `AccountIdentityAPI.ets` 的 `verifyAndIssueTicket`、`bindIdentity`、`changeIdentity` 当前使用 `Record<string,string>`，实现前必须改为显式 request class/interface，符合 ArkTS 严格类型门槛。

官方资料：

- `Universal Keystore Kit 简介`：`https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/huks-overview`，用于身份凭证或后续敏感 ticket 保护边界；本方案仍要求 verification ticket 仅驻留内存。
- `取消网络请求（ArkTS）`：`https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/remote-communication-netcancle-arkts`，用于页面退出或账号切换时取消未完成请求的策略参考。

### 4.4 注销、退出登录与会话清理

目标：退出登录走认证模块清理；注销走身份验证、最终确认、`POST /api/v1/deactivation/`，成功后本地登出。

iOS 证据：`AccountDeactivationFlowState`、`SubmitAccountDeactivationUseCase`、`DefaultAccountManagementRepository.submitDeactivation`；成功后 `SignOutUseCase.execute()` 与 `sessionStore.setSignedOut()`。

HarmonyOS 实现路径：

- 保留 `SettingsPage.onSignOut()` 的 `SignOutUseCase` 路径，但新增确认弹窗和失败反馈，不应无提示直接退出。
- 新增 `AccountDeactivationFlowState.ets` 与注销页面组件。
- `DeactivationAPI.ets` 已有 `DeactivationRequest`，但 `verification` 仍为 `Record<string,string>`；实现前补 `DeactivationVerificationPayload` typed union 或显式 class。
- 注销成功后调用 `container.signOut.execute()`、`lifecycle.onLocalSignOut()`、`sessionStore.signOut()`；账号级通知、缓存、AI、文件清理由 `AccountSessionRuntime` 和各模块注册表负责。

官方资料：

- `promptAction.showDialog` 可通过 ArkUI 弹窗能力承接最终确认；需按目标 SDK 官方 API 复核具体调用。
- `Universal Keystore Kit` 用于确保 Token、设备密钥、身份凭证不落普通 Preferences。

本地示例：

- `.../LiveStreaming/commons/server/src/main/ets/handler/interceptor/TokenRefreshInterceptor.ts`：可借鉴刷新后重放一次的边界；禁止复用其不完整安全存储与单飞策略。
- `.../LiveStreaming/commons/utils/src/main/ets/storage/preference/PreferenceUtil.ts`：只能借鉴普通状态存储形态；禁止保存 Token、OTP、verification ticket 或打印 value。

### 4.5 日志、反馈与测试

目标：账户管理所有失败要有用户反馈和脱敏诊断；测试必须覆盖状态机、API payload、会话清理和路由分流。

HarmonyOS 实现路径：

- 可恢复业务错误通过 `NotificationClient` 或页面 alert 展示；敏感字段不出现在文案。
- 所有 API 请求沿用 `SupportNetworkEngine` Request ID；日志只记录 operation、provider、scene、requestId，不记录 OTP code、Token、identity token、手机号全量、邮箱全量。

后端待确认项：

- Account Identity 与 Deactivation 是否有后台管理 API；是否复用同一 service。
- provider 枚举在 HarmonyOS 是否为 `huawei`、`phone`、`email`，是否继续保留 `apple` 只作为 iOS provider。
- 响应包裹 `code/msg/data`、业务错误码、OTP 限流码、ticket 过期码、注销幂等规则。
