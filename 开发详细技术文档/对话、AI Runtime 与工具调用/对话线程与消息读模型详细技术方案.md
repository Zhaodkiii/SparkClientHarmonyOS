# SparkClientHarmonyOS｜对话线程与消息读模型详细技术方案

> 核验日期：2026-07-22。本文与《消息发送、附件与同步管线详细技术方案》共享 `ChatRepository`、RDB schema、cursor 和账号生命周期，不重新定义底层状态机。

## 1. 对标范围与结论

iOS 使用 `ChatThreadEntity/ChatMessageEntity/ChatMessageBlockEntity/ChatSyncCursorEntity` 和 Repository 查询投影；鸿蒙使用同语义的 RDB 表和显式 ResultSet decoder。当前已支持线程列表、消息详情、工具/推理 block、tombstone 过滤、账号隔离和本地优先刷新；分页 UI 和块级冲突 reducer 仍需补齐。

## 3. 分层职责与请求链路

UI 只读取 `ChatRepository`，AI/同步/工具都通过同一 Repository 写入。读取顺序是本地快照优先，再触发线程级 pull；远端合并完成后局部重新查询，避免 UI 直接相信 WebSocket 携带的数据。

## 4. 核心关键技术与实现方案

### 4.1 线程列表

`listThreads(accountId)` 按 `is_pinned DESC, updated_at DESC` 查询，排除已删除线程。线程同步只更新标题、成员、模型参数、置顶、图标、删除状态和服务端时间，不拉消息正文。

### 4.2 消息窗口

`listMessages(accountId, threadId)` 按创建时间升序读取非 tombstone 消息，再按 `order_key/created_at` 加载 blocks。消息头和 block 分表，流式文本/推理/工具更新不重写整条消息。

### 4.3 幂等与版本

消息主键为 `(account_id, client_id)`，远端幂等键为 `client_message_id`；block 主键为 `(account_id, block_id)`，revision 与 orderKey 保留。远端重复 pull 可安全 upsert；旧 cursor 不推进。

### 4.4 账号生命周期

所有读写均带 account ID。登出/切换顺序：停止 WebSocket → bump MessageRunActor generation → 删除消息、块、线程、cursor、附件任务、审计记录 → 清理 AI/文件运行态。旧异步回调不会写入新账号。

## 9. 风险与待确认项

- 服务端当前 cursor 仍以时间/tie-breaker 编码，客户端不解析。
- 线程删除 UI 尚未接入 `thread-delete`；不可把本地物理删除当作远端删除完成。
- 健康卡片、工具 payload 和消息附件属于敏感健康信息；日志只能保留短 ID、数量、错误类别和 request ID。
