## 3. 分层职责与请求链路

本地优先链路：`ChatTabPage → SendChatMessageUseCase → ChatRepository → ChatOrchestrator/MessageRunActor → syncState=pending → ChatSyncEngine → ChatRemoteAPI → SparkService ACK`。

实时链路：`WebSocket chat.sync.updated → ChatSyncEngine single-flight → thread-pull/pull → ChatRepository upsert`。WebSocket 只作提示，不能作为消息事实源。

| 阶段 | 成功 | 失败/恢复 |
| --- | --- | --- |
| 写用户/助手占位 | UI 立即显示 | RDB 错误阻断本次发送 |
| AI 流式 partial | 稳定 block ID + revision 更新 | 取消保留已生成内容 |
| Outbox push | ACK 后 `syncState=synced`、delivery=`sent` | 保留 `failed`，下一轮重试 |
| pull | 页内全部 upsert 成功后推进 cursor | 旧 cursor 保留 |
| WebSocket | hint 触发 pull | 指数退避重连；鉴权失败停止 |

## 4. 核心关键技术与实现方案

### 4.1 RDB 与读模型

`chat_thread`、`chat_message`、`chat_message_block`、`chat_sync_cursor`、`chat_attachment_download`、`chat_tool_audit` 共用 `spark_client.db` 和 `AppRdbWriteQueue`。所有查询带 `account_id`；账号退出先停 realtime，再清除上述所有表。

### 4.2 Outbox 与 ACK

`ChatRepository.listOutbox` 读取 `pending/failed`；`ChatSyncEngine.pushOutbox` 先整包 `/sync/push/`，再发送 `block_updates`，服务端 ACK 后仅更新本地 server ID/server time，避免客户端用本地时间覆盖服务端事实。

### 4.3 游标与幂等

游标键与 iOS 一致：`chat.main`、`chat.thread.cursor`、`chat.thread.message.cursor.<threadID>`。收到分页后只有在本页消息全部合并成功时保存 cursor；同 cursor 或 `has_more=false` 停止，最多 20 页防止死循环。`client_message_id`、block ID 和 `dedupe_key` 是幂等键。

### 4.4 WebSocket

使用 `@kit.NetworkKit` `webSocket.createWebSocket()`；服务端当前 middleware 支持 query `token`，因此连接 URL 使用短生命周期 access token，生产日志不得输出该 URL。断线按 1/2/4…30 秒重连，事件仅解析 `chat.sync.updated` 并触发 REST pull。

### 4.5 附件

消息字段 `attachments_json` 保存可同步的附件 metadata，不保存二进制；发送端通过系统相册/文件选择器，使用 `FileTransferService.upload`（businessType=`chat_attachment`、businessId=`previewId`、私有文件）上传，图片通过 Core Vision Kit 做本机 OCR，并将阶段写入 UI。远端入站为有远端文件身份或 HTTP(S) URL 的附件创建 `chat_attachment_download` 去重任务；`ChatAttachmentPipeline` 通过现有 `FileTransferService.cachedURL/download` 落盘并记录 completed/failed。

## 5. 接口契约与数据模型

| API | method/path | 请求核心字段 | 响应核心字段 | 鉴权/策略 |
| --- | --- | --- | --- | --- |
| push | POST `/api/v1/ai/chat/sync/push/` | `messages[]`、`block_updates[]` | `accepted_messages[]`、`accepted_block_updates[]` | Bearer；幂等；重试 |
| pull | GET `/api/v1/ai/chat/sync/pull/` | `cursor`、`thread_id`、`limit` | `cursor`、`messages[]`、`has_more` | Bearer；只推进成功 cursor |
| thread-pull | GET `/api/v1/ai/chat/sync/thread-pull/` | `cursor`、`limit` | `threads[]`、`has_more` | Bearer |
| thread-push | POST `/api/v1/ai/chat/sync/thread-push/` | `threads[]` | `threads[]` | Bearer；幂等 |
| thread-delete | POST `/api/v1/ai/chat/sync/thread-delete/` | `thread_ids[]` | `thread_ids[]` | Bearer；软删 |
| realtime | WS `/ws/chat/sync/` | query `token` | `chat.sync.connected`、`chat.sync.updated` | JWT |

消息/线程字段使用后端 snake_case，ArkTS 通过 `ChatRemoteAPI` 显式 decoder 转为领域模型；Token 不进入 RDB、Preferences、审计或日志。

## 9. 风险与待确认项

1. WebSocket query token 会出现在连接 URL，服务端当前只确认该鉴权方式；需要评估 Network Kit 是否可设置 Authorization header，并在支持后切换。
2. 后端 cursor 当前由时间戳+tie-breaker 编码，客户端按 opaque string 保存，不解析其内部结构。
3. HarmonyOS 健康数据没有在当前工程中发现等价于 iOS HealthKit 的已接入执行器；生产改为 `HealthUnavailableExecutors`，`HealthMockExecutors` 只能作为测试桩。
4. 附件上传/OCR 和消息编辑/删除 UI 尚未完成真机验收；线程软删除、消息重试、块级延迟同步和下载任务消费已具备领域/同步实现。
