# SparkClientHarmonyOS｜工具调用与审计详细技术方案

## 1. 对标范围与结论

- **后端与后台管理证据：** 工具名与 `SparkService/ai_config` 的 `SparkToolName` rawValue 对齐；客户端不自创平行工具名。
- **参考端与证据：** iOS `SparkClient/Projects/Core/AIRuntime/ToolHub/` + `总领文档/对话、AI Runtime 与工具调用/工具调用与审计需求.md`。
- **HarmonyOS 目标端与现状：** `entry/src/main/ets/Core/AI/Runtime/ToolHub/` 已从联调级升级为与 iOS 同构的 Schema/路由/Consent/审计/执行骨架；健康读工具在生产默认明确返回未接入，不伪造设备数据。
- **目标用户能力：** 聊天路径可出站全量工具定义、`/audit_tools`、`debug_echo`、画布内存工具；未接入业务工具返回显式 unsupported；敏感结果在无 UI Coordinator 时拒绝外传。
- **结论：** 中枢架构 **部分对齐**；业务 Executors（知识/记忆/联网/问报告等）仍需逐个接入；健康真实 Kit 与 ToolInteraction UI **待实现**。

## 3. 分层职责与请求链路

```text
SendChatMessageUseCase
  → ChatOrchestrator.generateReply
      → ToolHub.runIfNeeded / listToolDefinitions / executeToolCall
          → HealthUnavailableExecutors | unsupported | canvas
          → AppleHealthToolConsentPolicy (+ optional Coordinator)
          → ToolAuditStore
          → ToolSideEffectSink
```

| 阶段 | 触发 | 成功 | 失败/清理 |
| --- | --- | --- | --- |
| 斜杠 bypass | `/audit_tools` `/tool …` | kind=tool | 未命中则进推理 |
| 出站 tools | inference flags | 过滤知识/联网/白名单 | useTools=false → 空 |
| 执行 | model tool_calls | 回灌 role=tool | 未识别工具文案 |
| Consent | 五类 Health + sensitive + 非 LOCAL | 放行或 blocked hint | 无 Coordinator 时阻止外传并记 warn |

## 4. 核心关键技术与实现方案

### 4.1 ToolHub 门面

对齐 iOS `executeToolCall` / `runIfNeeded` / `toolDefinitions`；鸿蒙 `listToolDefinitions(allowed, useKnowledgeBag, useWebSearch)`。

### 4.2 健康数据（平台差异）

- **iOS：** HealthKit 真实读取。
- **HarmonyOS（当前）：** `HealthUnavailableExecutors` 明确返回未接入；`HealthMockExecutors` 仅保留为测试桩，**禁止**生产路由调用或声称已接系统健康正式 API。
- 后续：替换为华为健康/运动健康 Kit，并保持同一 `SparkToolName` 与 `ToolExecutionResult` 契约。

### 4.3 Consent

- 运行时策略对齐 iOS：仅五类 Health 读工具。
- `ToolInteractionCoordinating` 供 UI 注入；未注入时阻止敏感结果出站并打 warn 日志。

## 9. 风险与待确认项

1. 无 Coordinator 时已阻止敏感结果外传；正式版仍必须注入 UI Coordinator 才能提供用户授权交互。
2. ToolPrompts 多语言尚未迁入 `string.json`。
3. 副作用 sink → MessageRunActor 富卡片映射未完成。
4. 健康 mock 不得被产品文案描述为真实设备数据。
